## 一、外部重要事件

### 1.1 ICS 解析增强（纯函数，零依赖）

`normalizeIcsEvent` 输出扩展为外部事件对象（不改变 P4.3 文件导入为 Task 的语义，两条出口分开）：

```js
{
  uid,               // ICS UID；缺失回退 'h:'+hash(title|dtstart|dtend) 内容哈希
  title, description, location,
  startDate, endDate, time, allDay,
  tzid,              // DTSTART 的 TZID 参数（仅记录，见时区说明）
  status,            // 'confirmed'（默认）| 'cancelled'（STATUS:CANCELLED）
  sequence,          // SEQUENCE 数字，缺失 0
  createdAt, updatedAt,   // CREATED / LAST-MODIFIED / DTSTAMP（ISO，来源支持时）
  recur,             // 复用现有 rruleToRecur
  remindAhead        // 取 VALARM 中 TRIGGER 负向时长分钟（-PT15M→15，-PT0D→0）；无 VALARM 为 null
}
```

`parseIcs` 增加扫描：UID、LOCATION、SEQUENCE、CREATED、LAST-MODIFIED、DTSTAMP、STATUS:CANCELLED、DTSTART/DTEND 的 `TZID` 参数、`BEGIN:VALARM…TRIGGER…END:VALARM`。
缓存包装升级为 `{syncedAt, version:2, events}`。

### 1.2 稳定身份与差异同步（纯函数）

- `extEventKey(subId, ev) = subId + '#' + ev.uid`
- `diffExtEvents(oldList, newList)` → `{added, updated, removed, cancelledKeys}`：按 key 匹配；`updated` 判定（sequence 增大或 updatedAt 变化或内容哈希变化）；旧有新无 = removed；新列表 status=cancelled = cancelledKeys。
- 刷新策略：成功才覆盖缓存；解析失败/网络失败保留旧缓存，订阅打 `stale` 标记（UI 显示"数据可能过期，上次成功同步 …"）。
- 主进程 `cal-sub-fetch` 增加可选请求头 `If-None-Match/If-Modified-Since`，识别 304 → `{ok:true, notModified:true, etag, lastModified}`；订阅定义存 `etag/lastModified`。
- 自动刷新按每订阅 `refreshIntervalMin`（60/180/360/1440，-1=仅手动）到期才拉，替换现有固定每小时全量。

### 1.3 订阅管理增强

订阅定义新增 `refreshIntervalMin`（默认 60）、`etag`、`lastModified`（迁移兜底）。UI 增加：编辑（名称/URL/频率）、频率下拉、过期/错误状态区分、最后同步时间（现有）。

### 1.4 外部事件提醒（复用现有提醒链路，独立账本）

新 localStorage 键：
- `calEventCfg`：`{ [extKey]: {remind:boolean, aheadMin:number} }` —— 单事件提醒开关/提前量覆盖；进 business 备份。
- `calRemindLedger`：`{ [extKey+'|'+date]: {version, at} }` —— 防重复；version=sequence||updatedAt，事件更新后允许再次提醒；不进备份（运行时状态，STATE 类）。

纯函数 `dueExtReminders(subs, caches, cfg, ledger, now)` → 待提醒列表（可单测，不碰 DOM/通知）：
- 只看启用订阅的最新缓存；`cancelled` 与已移除事件不提醒；
- 具体时间事件：触发时刻 = 本地时间 − aheadMin（优先级：单事件覆盖 → 事件 VALARM → 全局 `remindAheadDefault`）；
- 全天事件：事件开始日 **09:00 本地**提醒一次（多日全天只在首日）；
- 重复事件按现有 `recurMatchesDate` 命中日投影，每命中日一次；
- 刷新后事件被取消/移除：其未发提醒作废、ledger 条目惰性清理。

`checkExtReminders(now)` 消费纯函数结果，复用 `Notification` + `playChime(CHIME.remind)` + toast（文案标注"外部事件 · 来源名"）；通知点击打开详情浮层（不走 gotoSearchResult）。在现有 `checkReminders()` 末尾调用，互不干扰。

### 1.5 详情浮层与转存

- `buildCalEventDetail(ev, sub)`：标题、来源、起止/全天、地点、状态（已取消置灰）、描述、最后同步时间、提醒开关 + 提前量选择、**"存为本地事项"**按钮（打开现有 add-form 预填，用户主动保存才落 Task；默认不转换）。
- 周/月视图订阅条目点击由 toast 改为打开该浮层。

### 1.6 Provider 边界（本期不接真实第三方 API）

- 订阅对象保留 `providerType` 字段，本期仅 `'ics-url'`；结构上为未来 Provider 预留。
- Google/Outlook 等 OAuth 日历本期**不接入**：需 OAuth 客户端注册、redirect/loopback 授权、令牌本地加密存储、可能的厂商审核与费用；在 UI 与本方案中明示，不虚构 API、不自建云服务。

## 二、甘特图阶段层级

### 2.1 数据模型（只增字段）

- phase：`{id,name,order,startDate:'',endDate:''}`；`loadProjects` 迁移补齐。
- 新增 `setPhaseDates(projectId, phaseId, startDate, endDate)`：仅改阶段日期；纠正倒挂（交换）；**绝不自动改动事项日期**；revision++。
- `buildPhaseBlock` 每项增加起止 `date` 输入与持续时长显示。

### 2.2 纯函数（可单测）

- `groupTasksByPhase(project, tasks)` → `[{phase, tasks}…, {phase:null, tasks}]`：阶段按 order；空阶段保留成组；未分阶段事项归末尾 null 组（有事项才成组）。
- `phaseProgress(tasks)` → `{done,total,pct}`：total=0 → `{0,0,0}`，杜绝除零。
- `phaseRangeViolations(phases, tasks)` → `[{taskId, phaseId, dir:'before'|'after'}]`：仅当阶段与事项都有日期时判定。
- 阶段横条起止：优先阶段自身日期；无日期时不画条（虚线占位 + "未设日期"提示）。

### 2.3 渲染（增量改造两个现有甘特图，不重写）

- 时间轴范围纳入阶段日期；
- 每个阶段一行**阶段父级行**（左：▸/▾ 展开控件 + 色点 + 名称 + `M/D~M/D（n天）` + 进度 `x/y · pct%`；右：阶段横条，样式与事项条明显区分）；
- 阶段下事项行缩进，结构仍是 `.gantt-row > .gantt-bar`，**现有拖拽改期/点击编辑/缩放/横向滚动/今天线全部保留**；阶段行不可拖拽；
- 收起：模块级 `ganttPhaseCollapsed: Set(projectId+':'+phaseId)`，仅切换事项行 `hidden`，**不改 Task 数据/排序/日期**；默认展开；状态仅存会话内（重启还原默认）；
- 超范围事项：`.gantt-bar.over-range` 警告描边 + title"超出阶段 X 日期范围"，只提示；
- 空阶段：独立显示父级行 + "0 事项"，进度 0%；
- 未分阶段事项：有阶段时显示在末尾"未分阶段"组（无父级条）；
- **兼容关键**：项目没有任何 phase 且事项均无 phaseId 时，甘特图与现状像素级一致（走原平铺路径）。总览甘特图同样在项目内套阶段层；"未归类"虚拟组保持现状。

### 2.4 样式

styles.css 新增 `.gantt-phase-row/.gantt-phase-name/.gantt-phase-bar/.gantt-phase-toggle/.gantt-phase-meta/.gantt-bar.over-range`，复用现有色阶 `phaseColor(i)`。

## 六、平台差异与外部服务依赖

- 平台：渲染层逻辑平台无关；网络走主进程 Node 内置 http/https，Windows/macOS/Linux 一致；无新依赖。
- 时区/DST：应用约定"时间即本地墙钟"。ICS 中 `Z` 结尾 UTC 时间转本地；浮动时间与带 TZID 但无 VTIMEZONE tzdata 的时间按本地处理（详情中显示原始 TZID 提示）；夏令时由系统 `Date` 自动遵循。VALARM 仅支持负向 `DURATION`（-PTxM/-PTxH）与 `-PT0D`，绝对触发时间 VALARM 忽略并在详情提示。
- 外部服务：本期仅标准 iCalendar/ICS（文件导入 + http(s) 订阅 URL），不自建云、不接 OAuth；Google/Outlook 等需账号授权的 Provider 明示依赖（OAuth 客户端、令牌存储、厂商费用/审核/隐私）后另行评审。
- 密钥：不新增任何凭据存储；同步密钥现状已排除在所有备份外。
