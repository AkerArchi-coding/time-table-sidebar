# P2 阶段实施方案：番茄钟绑定事项 / 提醒增强 / 甘特图交互 / 同步预留

## Context

P1 已完成基础设施（备份/导出、数据目录迁移、多显示器）。P2 聚焦四个核心功能增强，全部为增量改动，不破坏现有功能，不引入新依赖。

## 功能 1：番茄钟绑定事项

**目标**：番茄钟可关联具体事项，专注完成后自动记录到该事项。

**改动点**（`src/renderer/app.js`）：

1. `POMO` 对象（L2684）新增字段：`taskId: null, taskTitle: ''`
2. `buildPomodoro(panel)`（L2851）在 `.pomo-stage` 上方插入事项绑定区：
   - 下拉选择未完成事项（`loadEvents().filter(e => !e.done)`，显示标题+日期）
   - 选中后 `POMO.taskId/taskTitle` 赋值；提供「解除绑定」按钮
3. `pomoTick()`（L2757）work 阶段结束时：若 `POMO.taskId` 存在 → 该事项 `pomoCount++`，并向 `pomoTaskLogs` 追加一条记录 `{taskId, taskTitle, minutes: POMO.workMin, ts: ISO}`，然后 `updateEvent` + `savePomoTaskLogs`
4. `pomoReset()` 清空 `POMO.taskId/taskTitle`
5. 事项右键菜单新增「开始番茄钟」项：设置 `POMO.taskId` 并打开 pomodoro 工具面板

**数据结构变更**：
- event 新增 `pomoCount`（默认 0）→ `loadEvents` 迁移补齐
- 新 localStorage key `pomoTaskLogs`：`{ date: 'YYYY-MM-DD', logs: [{taskId, taskTitle, minutes, ts}] }`，每日重置
- `pomoStats` 结构不变（仍为 `{date, count}`）

**验证**：选事项 → 开始番茄钟 → 等工作阶段结束（或临时调短时长测试）→ 事项 pomoCount+1、pomoTaskLogs 有记录；重置后绑定解除。

## 功能 2：提醒系统增强（提前提醒 + 贪睡）

**目标**：支持提前 N 分钟提醒，提醒后可贪睡 5 分钟。

**改动点**（`src/renderer/app.js`）：

1. `buildTaskForm`（L384 日期行后）新增「提前提醒」下拉（0/5/10/15/30 分钟）
2. `bindFormEvents.save`（L458）fields 增加 `remindAhead: Number(select.value) || 0`
3. `checkReminders()`（L2568）改造：
   - 触发条件：`eventStart(ev) === today && time` 存在，计算 `triggerTs = todayDate + ev.time - remindAhead*60000`；`now >= triggerTs` 且 `(!ev.snoozeUntil || now >= ev.snoozeUntil)`
   - 触发后：若 `remindAhead > 0`，仅首次（提前）提醒时标记；到点本身若已提前提醒过则不再重复（用 remindedKeys 含 `id|date|ahead` 与 `id|date|ontime` 区分）
   - 简化方案：remindedKeys key 用 `id|date`，触发后标记；贪睡时从 remindedKeys 移除该 key 并设 `snoozeUntil`，使其可再次触发
4. 新增 `showReminderToast(ev)`：toast 内含「贪睡 5 分钟」按钮 → 设置 `ev.snoozeUntil = Date.now() + 300000`，`updateEvent`，并从 `remindedKeys` 删除 `id|date`

**数据结构变更**：
- event 新增 `remindAhead`（默认 0）、`snoozeUntil`（默认 0）→ `loadEvents` 迁移补齐

**验证**：设 time=当前+10min, remindAhead=5 → 5 分钟后弹提醒 → 点贪睡 → 再 5 分钟后再次提醒。

## 功能 3：甘特图交互改进

**目标**：鼠标滚轮横向滚动、Ctrl+滚轮缩放列宽、回到今天按钮。

**改动点**（`src/renderer/app.js` + `styles.css`）：

1. `GANTT_DAY_W` 常量（L1100）改为 `GANTT_STATE = { dayW: 28 }`，全文 ~15 处 `GANTT_DAY_W` 替换为 `GANTT_STATE.dayW`
2. `buildGantt`（L1120）和 `buildOverviewGantt`（L1210）顶部插入 toolbar：`[－] [＋] [回到今天]`，dayW 范围 16~56，步进 4
3. 缩放后重渲染当前视图（调用 `render()` 或局部 rebuild）
4. `bindGanttDrag`（L1351）末尾对 `.gantt-right` 绑 `wheel` 事件：
   - `e.preventDefault()`
   - 若 `e.ctrlKey`：`GANTT_STATE.dayW = clamp(dayW - Math.sign(e.deltaY)*4, 16, 56)`，重渲染
   - 否则：`el.scrollLeft += e.deltaY || e.deltaX`
5. 「回到今天」：计算 todayOffset，`scrollLeft = todayOffset * dayW - clientWidth/2`

**样式**（`styles.css`）：新增 `.gantt-toolbar`、`.gantt-zoom-btn` 样式（紧凑，与现有暗色主题一致）

**验证**：滚轮横向滚动；Ctrl+滚轮缩放列宽 16~56px；点「回到今天」今日虚线居中。

## 功能 4：扫码配对 / 局域网同步预留（仅接口，不实现网络）

**目标**：预留设备标识、配对数据结构和 IPC 占位，为未来局域网同步铺路。

**改动点**：

1. `src/renderer/app.js` 启动时生成 `deviceId`（UUID v4）存 localStorage `deviceId`；新 key `syncPairs`：`[{deviceId, name, platform, pairedAt, status}]`
2. event 预留 `lastSyncAt` 字段（迁移补空串）
3. `syncLog` action 枚举增加 `pair-create` / `pair-remove`
4. `src/main.js` 注册 4 个 IPC 占位 handler，均返回 `{ ok: false, code: 'not_implemented', hint }`：
   - `sync-pair-start`：生成配对码（占位）
   - `sync-pair-scan`：扫描局域网设备（占位）
   - `sync-send`：发送数据到对端（占位）
   - `sync-receive-cb`：注册接收回调（占位，实际不监听）
5. `src/preload.js` 暴露 `window.timetable.syncPairStart / syncPairScan / syncSend / onSyncReceive`
6. 设置面板新增「设备同步」分组（占位）：显示本机 deviceId，「配对新设备」按钮调用 `syncPairStart` 后 toast「功能开发中」

**验证**：DevTools 查 `localStorage.deviceId` 已生成；调用 `window.timetable.syncPairStart()` 返回 `not_implemented`。
