# P4 实施方案：日历视图增强 + 外观与系统集成 + iCal 互通 + 提醒与同步增强

> 约束（沿用 P1~P3）：增量开发，不推翻现有架构；现有功能不受影响；数据仅存本机；零新增 npm 依赖；代码注释中文；每批独立 commit、测试通过再进下一批。

## P4.1 外观与系统集成（先做：低风险，主进程为主）

### 主题：亮色/暗色 + 强调色
- 现状：styles.css 全量暗色硬编码（无 CSS 变量）。全量变量化回归风险大，**采用「关键变量 + body 类覆盖」最小方案**：
  - 抽取 ~12 个核心变量到 `:root`（表面背景/卡片背景/主文字/次文字/边框/强调色/强调弱背景等），暗色值 = 现有值，视觉零变化；
  - `body.light` 覆盖这组变量为亮色值（逐条对照现配色体系调亮，透明度结构不变）；
  - 强调色独立变量 `--accent`（当前蓝）+ 4~5 个预设色板（蓝/青/紫/橙/绿），JS 写 `document.documentElement.style.setProperty`；
- 设置面板新增「外观」组：暗色/亮色二选一 + 强调色色板圆点；持久化 `uiTheme`（localStorage，备份键同步加入 BUSINESS_KEYS）；
- 范围控制：不整改全部 2196 行内的散落硬编码色（图表/甘特等局部色先保留，仅明显刺眼的对比处随变量走）；不做自定义取色器。

### 开机自启（回答用户疑问：不需要单独的注册表程序）
- Electron `app.setLoginItemSettings({ openAtLogin })` 在 Windows 上**本身就是写注册表** `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（当前用户级，无需管理员、无需服务、无需额外程序）；
- 便携版坑：启动时 `process.execPath` 指向临时解压目录 → 用 `process.env.PORTABLE_EXECUTABLE_FILE`（electron-builder 便携版自带）兜底真实 exe 路径；封装 `resolveLaunchExe()` 纯函数（可单测）；
- 主进程 IPC：`autostart-get` / `autostart-set`（写入时显式传 `path` + `args: []`）；设置面板「系统」组加开关，回显 `app.getLoginItemSettings()`；
- 失败（如策略禁用）toast 提示不崩溃。

### 通知点击直达
- 渲染层 `new Notification` 加 `onclick`：唤起窗口（主进程 `show-window` IPC：显示+展开侧边栏）+ 定位事项（today 视图 + 打开该事项编辑表单，复用 openTool/表单逻辑）；
- 提醒通知、番茄钟完成通知均接入；点击后通知自动关闭。

### 测试
- `resolveLaunchExe()` 单测（便携环境变量兜底、普通路径直取）；主题持久化键入备份键单测；通知直达启动验证。

## P4.2 日历视图增强（动渲染核心，回归重点）

### 月历视图（新增第 5 视图）
- viewTabs 加「月历」：6×7 网格（周一开头，复用 startOfWeek），格子显示日期号 + 当日事项小条（最多 3 条，超出 +N），事项条颜色按分类，完成项划线保留可见（沿用偏好）；
- 数据复用 `getEventsByDate`（重复事项投影天然支持）；格子背景透明度叠加热力效果（事项数 0~5+ 分档，轻量热力图）；
- 交互：点击日期 → 切到周视图并定位该日；今日高亮；上/下月切换 + 回今天按钮（复用 headerActions 插槽）；
- 项目工期：有起止日期的项目在月历格子底部显示进度细条。

### 周视图拖拽改期
- 周视图事项卡片支持拖拽到其他日卡片：mousedown 自实现（HTML5 DnD 在无边框透明窗口表现不稳），拖起显示半透明浮层，落点高亮目标日；
- drop → `updateEvent(id, { date })`（重复事项模板拖拽 = 改起始日，虚拟事项拖拽 = recurOverrides「仅本次」改期——P3.2 已有 override 机制）；批量模式禁用拖拽；
- 拖拽只做改期不改时间；甘特图不做拖拽（列宽可变，落点语义复杂，明确不做）。

### 测试
- `buildMonthGrid(year, month)` 纯函数单测（6 周固定、月末边界、跨年）；拖拽日期换算纯函数；重复事项 override 改期已有测试补拖拽路径用例。

## P4.3 数据互通 iCal（纯新增，零依赖手写解析器）

### 导出 .ics
- 设置面板/备份区加「导出日历 (.ics)」：events + projects 起止 → VCALENDAR/VEVENT；
- 字段映射：SUMMARY=title、DESCRIPTION=备注+tags、DTSTART/DTEND=本机时区浮点时间（无 TZID 简化）、STATUS/完成态、RRULE：daily/weekly/monthly/weekdays → FREQ+INTERVAL+UNTIL（weekly 带 BYDAY）；
- 复用 backupExportDialog 保存模式；文件名默认 `日程导出-YYYYMMDD.ics`。

### 导入 .ics
- 手写解析器（零依赖）：行折叠（RFC5545 续行）+ BEGIN:VEVENT 块扫描 + 属性解析（含带参数的 DTSTART;VALUE=DATE）；
- RRULE 反向映射到 recur（FREQ=DAILY/WEEKLY/MONTHLY + UNTIL；weekdays 由 BYDAY=MO-FR 反推；不支持的 FREQ 落为不重复并在事项备注追加说明）；
- 导入预览面板（复用工具面板样式）：列出解析出的事项（标题/日期/时间/重复规则）+ 勾选 + 「导入到项目」下拉（默认未归类）；
- 去重：同项目下「标题+日期+开始时间」相同 → 默认跳过（面板显示重复标记）；
- 导入写 addEvent（tags 从 CATEGORIES 解析），自动写同步墓碑不需要（新增无冲突）。

### 测试
- 导出→导入往返单测（关键字段还原、RRULE 映射、行折叠、VALUE=DATE 全天事件、CRLF 处理）。

## P4.4 提醒与同步增强（收尾）

### 稍后提醒（应用内提醒条，不依赖系统通知按钮）
- Windows Web Notification 不支持操作按钮 → 做**应用内顶部提醒条**：提醒触发时侧边栏内出现提醒条（事项名+时间+「完成」/「稍后」按钮）；
- 「稍后」= 5 分钟后再次提醒（内存 snoozeMap，重启即清，符合轻量语义）；「完成」= toggleDone；
- 系统通知保持现状纯展示；设置加「提醒条」开关（默认开）。

### 定时自动同步
- 设置「自动同步」开关（默认关）+ 间隔固定 10 分钟（不做自定义，防复杂）；
- 仅当同步面板被打开过（会话已启动）且有已配对设备时生效；对每台设备 doSyncNow（UDP 发现 → lastIp 兜底），成功静默写 syncLog，失败静默跳过（连续失败 3 次写一条日志提示）；
- 窗口隐藏时暂停（复用 window-visible 事件），防止后台空转。

### 测试
- 贪睡调度逻辑单测（snooze 后下次触发时间、完成清除）；自动同步调度开关态单测。

## 实施顺序与里程碑

| 批次 | 内容 | 风险 | 验证 |
|---|---|---|---|
| P4.1 | 主题/开机自启/通知直达 | 低 | 单实例 + 单测 |
| P4.2 | 月历视图 + 拖拽改期 | 中高（动渲染核心） | 单实例 + 单测 |
| P4.3 | iCal 导入导出 | 低中（纯新增） | 单测 + 单实例 |
| P4.4 | 提醒条 + 自动同步 | 中 | 单测 + 单实例 |

顺序理由：P4.1 主进程为主风险最低先行；P4.2 动渲染核心趁状态好早做；P4.3 纯新增随时可插；P4.4 依赖同步/提醒现状稳定后收尾。

## 明确不做（防范围蔓延）
- 不做主题自定义编辑器/自定义取色器、不做亮暗之外的更多主题；
- 甘特图拖拽、月历格子内拖拽不做（周视图拖拽已覆盖核心诉求）；
- iCal 不支持 VALARM/VTIMEZONE/时区转换（按本机浮点时间处理）、不做 iCal 定时双向同步（仅手动导入导出）；
- 通知中心聚合不做（系统通知 + 应用内提醒条已覆盖）；
- 不引任何新 npm 依赖。
