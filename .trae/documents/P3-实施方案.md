# P3 实施方案：局域网同步落地 + 数据统计周报 + 事项效率增强 + 体验打磨

> 约束（沿用 P1/P2）：增量开发，不推翻现有架构；现有功能不受影响；全部数据默认仅存本机；零新增 npm 依赖（Node 内置 `http`/`dgram`/`crypto` 实现同步）；代码注释中文。

## 〇、沙箱测试安排（先回答：什么时候能开始沙箱测试？）

**现在就可以**。P1/P2 已交付的功能随时可用 `npm run dev` 实测。P3 期间每一批完成后都立即提供可实测状态，测试分三层：

1. **单元测试（node:test，零依赖）**：每批新增纯逻辑都配测试，与 P2 同方式（vm 沙箱加载 app.js），`npm test` 一键跑。
2. **单实例沙箱**：每批完成后 Electron `--dev` 启动实测 UI 与交互（统计图表、重复事项、搜索、快捷键）。
3. **双实例沙箱（P3.1 同步专用）**：同一台电脑启动两个互相隔离的应用实例，模拟两台设备：
   - 新增 npm 脚本 `dev:sync-a` / `dev:sync-b`，分别用独立 userData 目录（`./.sandbox/a`、`./.sandbox/b`）+ 独立端口 + 独立设备名启动；
   - `.sandbox/` 加入 `.gitignore`；
   - 验证流程：A/B 各自造数据 → 配对 → A 推 → B 拉 → 双向合并 → 删除传播 → 冲突（双方改同一事项）按更新时间决胜 → 校验载荷已加密。
   - 同一台机器配对走 `127.0.0.1`；真机验证再走局域网 Wi-Fi。

## P3.1 数据统计与周报（建议最先做：纯渲染层、零回归风险）

### 数据层补全
- 当前 `pomoTaskLogs` 只保存"当日"，跨天即清空，无法做趋势。新增持久化累积键 `pomoHistory`：
  - `[{date:'YYYY-MM-DD', count:n, minutes:m}]`，append 专注日志时同步 upsert 当日聚合（`appendPomoTaskLog` 内调用，不动现有当日日志逻辑）。
  - 备份模块 `BUSINESS_KEYS` 增加 `pomoHistory`。
- 事项完成记录已有充分原始数据（`events` 的 `done` + `createdAt`/`updatedAt`），无需新字段；统计按完成日期近似取 `updatedAt`（仅对 done 项），在文档/UI 中注明口径。

### 新增工具"统计"（rail 工具图标，TOOL_DEFS 增加 stats）
- 顶部区间切换：近 7 天 / 近 30 天。
- 卡片 1 专注趋势：DOM 柱状图（沿用甘特图暗色风格，不引图表库），每日柱子高度=分钟数，悬停 tooltip 显示次数+分钟。
- 卡片 2 事项概览：新增数、完成数、完成率（完成/新增），环形或进度条用纯 CSS。
- 卡片 3 分类分布：工作/个人/家庭三分类完成数横条。
- 卡片 4 项目排行：按完成事项数列出项目进度。
- 周报导出：汇总本周（周一~周日）完成事项清单（按项目分组）+ 专注总次数/分钟数 + 每日完成小条形，
  支持「复制到剪贴板」（Markdown 纯文本）与「导出 .md 文件」（复用现有 backupExportDialog 文件保存模式）。

### 测试
- 纯函数：`pomoHistoryUpsert(history, date, minutes)`、`buildStats(events, history, rangeDays)`、`buildWeeklyReport(events, projects, history, weekStart)` 全部独立成函数并配单测（边界：空数据、跨月、未来日期数据不计入）。

## P3.2 事项效率增强（重复事项 + 全局搜索；涉及渲染核心，回归重点）

### 2.1 重复事项
- 数据字段：events 增加 `recur: { freq: 'none'|'daily'|'weekdays'|'weekly'|'monthly', interval: 1, until: '' }`（默认 none；迁移兜底见 loadEvents）。
- **不物理展开副本**，渲染时动态投影：
  - `getEventsByDate` 对带 recur 的模板按规则判断该日是否命中，返回虚拟视图对象（复制模板字段 + `_recurDate` + `id` 用 `${ev.id}@${dateKey}` 复合键渲染）；
  - 周视图、甘特图、提醒轮询共用同一投影入口，保证三处口径一致。
- 完成态按日期记录：`recurDone` 对象（迁移兜底 `{}`），key 为 `eventId|dateKey`，值 true；勾选虚拟事项只写 override，不改模板 done。
- 编辑模板：标题/时间/分类修改作用于全部；支持「仅本次」改期（记录到 `recurOverrides: [{date, patch}]`，本期可只支持跳过/完成，改期如超范围再议）。
- 范围控制：freq 先做 不重复/每天/工作日/每周/每月 + 结束日期（可空=永久），不做"每 N 周自定义星期几"等复杂组合（interval 字段保留，UI 先只给 1）。
- 提醒：checkReminders 遍历时对命中的重复事项同样触发（按复合 key 去重，已有 remindedKeys 机制天然支持）。

### 2.2 全局搜索
- rail 工具或周视图头部增加搜索入口（优先头部搜索图标，不挤占现有布局）：
  - 关键字匹配 title + description，跨全部日期，结果按日期排序，显示日期/时间/标题/项目名；
  - 点击结果：若事项在当前 8 天窗口外，先翻页定位到所在周，再打开编辑（翻页复用现有 PAGE_STEP 机制）。

### 2.3 批量操作（列入本批但置末，视 2.1/2.2 完成情况再做）
- 事项右键/多选模式：批量改分类、改项目、删除；与"完成项保留可见+粗删除线"的现有偏好一致，删除仍走单条确认逻辑的批量版（一次确认列出数量）。

### 测试
- 纯函数：`recurMatchesDate(recur, startDate, targetDate)`（含工作日/月末/until 边界）、`projectVirtualEvents(events, dateKey)`、搜索过滤函数；均配单测。

## P3.3 体验打磨

### 3.1 全局快捷键（主进程 globalShortcut）
- 默认：`Ctrl+Alt+T` 唤出/隐藏侧边栏；`Ctrl+Alt+N` 直接打开快速添加并聚焦。
- 设置面板新增开关（默认开启唤出、默认关闭快速添加，避免打扰）；本期做开关不做自由录制。
- 失焦/退出时可靠反注册；注册失败 toast 提示但不崩溃（优雅降级）。

### 3.2 事项标签与筛选
- events 增加 `tags: []`（字符串数组，迁移兜底 []）；表单增加标签输入（逗号分隔，轻量实现，不做标签管理页）。
- 今日/事项视图顶部增加筛选 chips（从数据中聚合出现过的标签 + "全部"），选中后仅显示含该标签事项；筛选态不影响数据。

### 3.3 便签联动
- 快速便签工具栏增加「转为事项」：当前便签文本预填进快速添加（打开 quickadd 并带入标题，时间留空——符合"时间可选"偏好）；原便签保留不删。

### 3.4 细节
- 交互控件补充 `title`/`aria-label`（图标按钮无文字处）；搜索/标签等输入框焦点可见样式；
- 不改动现有字号体系，仅在新增面板对照现有密度，避免元素被裁切。

### 测试
- 标签聚合/筛选纯函数单测；快捷键主进程逻辑通过启动验证。

## P3.4 局域网同步落地（放最后：等新字段稳定，同步协议一次定型）

### 配对（零依赖，不引二维码库：配对码方案）
- A 设备点「等待配对」：主进程启动临时 HTTP 服务（随机端口）+ UDP 广播发现（dgram，内置），界面显示 **6 位配对码**（10 分钟有效，一次性）。
- B 设备「配对新设备」：自动发 UDP 发现同网段等待中的设备（列出设备名），选中后输入 6 位码完成握手；
  握手时双方各自生成 32 字节随机 secret 并交换（经配对码派生密钥加密通道，crypto 内置 AES-256-GCM）。
- 握手结果持久化：`syncPairs` 增加 `host/port/secret`（secret 存主进程 userData 下 `sync-secrets.json`，不进 localStorage/备份，避免备份泄露密钥）。
- 无法自动发现时提供「手动输入 IP」兜底。

### 同步协议（HTTP + AES-256-GCM 加密载荷）
- 被对端主动连接的一方临时起服务（同步会话期间监听，结束即关，不常驻）；或设置中开启"可被发现"时常驻（默认关闭，隐私优先）。
- 接口（Bearer 校验 + 载荷加密）：
  - `POST /hello`：交换 deviceId/name/平台；
  - `POST /sync/exchange`：双向各发一份"同步快照"（projects + events + tombstones + pomoHistory），合并在渲染层完成。
- 删除传播：新增 `syncTombstones`：`[{id, kind:'event'|'project', deletedAt, deviceId}]`；
  deleteEvent/deleteProject 时写墓碑（上限 500 条滚动）；对端合并时据此删除本地。
- 合并规则（渲染层纯函数 `mergeSyncData(local, remote)`）：
  - 按 id 对齐，updatedAt 新者胜；updatedAt 完全相同按 deviceId 字典序兜底（确定性，不抖动）；
  - 墓碑优先：任一侧已删除且删除时间晚于记录更新时间 → 删除；
  - 合并后更新各记录 `lastSyncAt`，保存并 render；写 syncLog（已有机制）。
- 触发方式：手动「立即同步」按钮（先做手动，稳后再考虑定时）；同步前后 toast 结果（新增/更新/删除各几条），失败给用户可读信息（对端不在线/配对码错误/网络不通）。
- 防火墙：首次监听时系统会弹防火墙提示，属正常；README/界面文案说明。

### 数据字段配合
- P3.2 的 recur/tags、P3.1 的 pomoHistory 都在同步快照内随整条记录传输，无需协议改造；
- backup.js 的 BUSINESS_KEYS 增加 syncTombstones（不含 secret）。

### 测试
- 纯函数单测：`mergeSyncData`（新增双向、修改 LWW、删除墓碑、同时修改冲突、墓碑与编辑竞争）、加解密往返（主进程 crypto 逻辑抽成可 require 的小模块 `src/main/sync-crypto.js`）。
- 双实例沙箱端到端（见"沙箱测试安排"）。

## 实施顺序与里程碑

| 批次 | 内容 | 风险 | 沙箱验证 |
|---|---|---|---|
| P3.1 | 数据统计与周报 | 低（纯新增页面） | 单实例 |
| P3.2 | 重复事项 + 搜索（+批量置末） | 中高（动渲染核心） | 单实例 + 单测 |
| P3.3 | 快捷键/标签/便签联动/细节 | 中 | 单实例 |
| P3.4 | 局域网同步 | 高（主进程网络/加密/合并） | 双实例 + 单测 |

每批独立提交 commit；每批完成后 `npm test` + 启动验证通过再进入下一批。顺序理由：统计零风险先交付价值；重复事项/标签会新增数据字段，放在同步之前定型，同步协议只需做一次；同步最复杂且依赖数据结构稳定，放最后。

## 明确不做（防范围蔓延）
- 不做云服务器/账号体系/外网转发（坚持本地与局域网，符合隐私优先）。
- 不做实时冲突协同编辑、不做同步冲突人工选择 UI（自动 LWW，syncLog 可追溯）。
- 不引图表库、二维码库、任何新 npm 依赖。
- 不做移动端适配与小程序。
